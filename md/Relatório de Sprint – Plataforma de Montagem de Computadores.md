- O que foi proposto durante a sprint
Durante esta etapa do projeto, o grupo teve como objetivo evoluir o sistema além do MVP
inicial, aprimorando funcionalidades já implementadas e iniciando integrações mais
completas entre o aplicativo e os serviços externos.
Nesta sprint foi proposto:
● Melhorar o fluxo de montagem de computadores, tornando a navegação mais
intuitiva.

● Aprimorar o sistema de verificação de compatibilidade entre peças.

● Implementar comparação de preços entre diferentes fornecedores.

● Finalizar o sistema de salvar e visualizar montagens do usuário.

● Iniciar melhorias de interface e experiência do usuário (UX).

O foco desta sprint foi refinar o produto existente e preparar a base para
funcionalidades mais avançadas nas próximas etapas do projeto.


- Quais atividades foram realizadas
Durante a sprint, o grupo realizou diversas atividades relacionadas ao desenvolvimento do
aplicativo.
Entre as principais atividades desenvolvidas estão:
● Implementação da listagem de peças compatíveis com base nas escolhas feitas
pelo usuário.

● Desenvolvimento da tela de visualização de montagens salvas.

● Integração entre front-end (React Native) e API backend para buscar peças e
preços.

● Ajustes na estrutura do banco de dados Supabase para armazenar montagens de
forma mais organizada.

● Implementação do cálculo automático do custo total da montagem.

● Testes de funcionamento do sistema em emuladores Android e dispositivos reais.

● Melhorias na interface das telas de seleção de peças e resumo da montagem.

● Organização do repositório do projeto e versionamento no Git.

Essas atividades contribuíram para tornar o sistema mais funcional e próximo do objetivo
final do projeto.

- Quais foram os principais desafios
Durante o desenvolvimento desta sprint, alguns desafios foram encontrados pela equipe.
Os principais foram:
● Implementação da lógica de compatibilidade entre peças, que exige validações
entre diferentes categorias de hardware (CPU, placa-mãe, memória, etc.).

● Integração entre front-end e backend, garantindo que as informações de peças e
preços fossem exibidas corretamente no aplicativo.


● Organização das estruturas de dados do banco, principalmente para relacionar
montagens com usuários e componentes.

● Tempo limitado para desenvolvimento, exigindo divisão eficiente das tarefas entre
os membros do grupo.

● Ajustes na responsividade das telas, para garantir boa visualização em diferentes
tamanhos de dispositivos.

Apesar das dificuldades, o grupo conseguiu contornar os problemas por meio de
colaboração e divisão adequada das tarefas.

- O que o grupo conseguiu concluir
Ao final da sprint, o grupo conseguiu concluir diversas funcionalidades importantes do
sistema.
Entre os principais resultados alcançados estão:
● Sistema funcional de login e cadastro de usuários.

● Implementação da montagem guiada de computadores, com seleção de peças
por categoria.

● Exibição de peças compatíveis conforme as escolhas do usuário.

● Sistema de salvamento de montagens no banco de dados.

● Tela de visualização das montagens salvas pelo usuário.

● Cálculo automático do custo total da montagem.

● Estrutura básica para comparação de preços entre lojas.

Esses resultados representam uma evolução significativa do projeto, aproximando o
sistema da versão final planejada.

- Opinião do grupo sobre a sprint
De forma geral, o grupo considera que a sprint foi produtiva e importante para a evolução
do projeto.
As funcionalidades implementadas permitiram transformar o sistema de um protótipo inicial
em uma aplicação com recursos mais completos. Além disso, a colaboração entre os

integrantes foi essencial para resolver problemas técnicos e garantir o progresso das
atividades.
A sprint também ajudou o grupo a compreender melhor os desafios do desenvolvimento
de sistemas reais, principalmente no que envolve integração entre diferentes tecnologias.

- Sugestões de melhoria
Para as próximas sprints, o grupo sugere algumas melhorias no processo de
desenvolvimento:
● Melhor planejamento das tarefas no início da sprint.

● Divisão mais clara das responsabilidades entre os integrantes.

● Maior tempo dedicado à realização de testes antes da entrega das
funcionalidades.

● Documentação contínua das funcionalidades desenvolvidas.

● Implementação de testes automatizados para reduzir erros no sistema.

Essas melhorias podem ajudar a tornar o processo de desenvolvimento ainda mais
organizado e eficiente nas próximas etapas do projeto.
